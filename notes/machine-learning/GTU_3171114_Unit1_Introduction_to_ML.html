🔎 Chapter Overview & Learning Outcomes

This unit lays the conceptual foundation of Machine Learning before any algorithm is studied. Instead of memorizing formulas, focus on understanding why ML exists, how it differs from traditional programming, and the vocabulary (hypothesis space, inductive bias, cross validation) that every later unit will reuse.

By the end of this unit you should be able to
  • Define Machine Learning and explain why it is needed.
  • Classify a given real-world problem into Supervised / Unsupervised / Semi-Supervised / Reinforcement learning.
  • Explain hypothesis space and identify it for a simple learning problem.
  • Explain inductive bias and why it is necessary for generalization.
  • Explain evaluation metrics and different cross-validation strategies, and justify when to use which.

1. Introduction to Machine Learning

1.1 What is Machine Learning?

Definition

Machine Learning (ML) is a field of study that gives computers the ability to learn from data and past experience to improve their performance on a task, without being explicitly programmed with fixed rules for every situation.

Remember — Mitchell's Formal Definition

"A computer program is said to learn from experience E with respect to task T and performance measure P, if its performance at T, measured by P, improves with experience E."

Quick memory trick: T‑E‑P → Task, Experience, Performance.

Real-world example

Task (T): Classifying an email as spam or not spam.
Experience (E): A large set of emails already labelled "spam"/"not spam".
Performance (P): Percentage of emails correctly classified.
As the system sees more labelled emails, its spam-detection accuracy (P) improves — this is learning.

1.2 Why Machine Learning?

  • Some tasks are too complex to hand-code rules for (e.g., face recognition, speech recognition).
  • The environment/data keeps changing, so a fixed program becomes outdated (e.g., fraud patterns).
  • Large volumes of data are available today, which ML can exploit to find hidden patterns.
  • ML personalizes decisions (e.g., movie/product recommendations) which is impossible with static rule sets.

2. Different Types of Learning

Based on the kind of "experience" (data) available, learning is broadly divided into four categories.

2.1 Supervised Learning

Definition

Learning from a dataset where every input is paired with a known, correct output (label). The model learns a mapping f: X → Y and is used to predict labels for new, unseen inputs.

Key Point

Supervised = "Learning with a teacher/answer key." Two main sub-types: Classification (discrete output, e.g., Yes/No) and Regression (continuous output, e.g., price).

Real-world example

A student learning from solved examples in a textbook where each problem already has the correct answer given — comparable to predicting house prices from past sale records (area, location → price).

2.2 Unsupervised Learning

Definition

Learning from data that has no labels. The model tries to find hidden structure, patterns, or groupings in the data on its own (e.g., clustering, association).

Real-world example

Grouping customers of a supermarket into segments (budget shoppers, premium shoppers) purely based on purchase behaviour — nobody tells the algorithm the "correct" group in advance.

2.3 Semi-Supervised Learning

Definition

Learning from a dataset that has a small amount of labelled data and a large amount of unlabelled data. It combines ideas of both supervised and unsupervised learning to improve accuracy without the high cost of labelling everything.

Real-world example

A photo app where a user manually tags a few photos with family members' names; the app then uses those few labels plus thousands of unlabelled photos to auto-tag the rest.

2.4 Reinforcement Learning

Definition

Learning where an agent interacts with an environment, takes actions, and receives rewards or penalties. The agent learns a policy that maximizes total cumulative reward over time — there is no fixed "correct answer" dataset, only feedback.

Real-world example

Training a dog with treats: the dog is not shown a labelled dataset of "correct actions" — it tries actions, gets a treat (reward) for the right one, and a scolding (penalty) for the wrong one, gradually learning the best behaviour. Self-driving cars and game-playing AI (e.g., Chess/Go engines) use this approach.

3. Hypothesis Space

Definition

The hypothesis space (H) is the set of all possible functions/models that a learning algorithm is allowed to consider as candidate solutions for mapping inputs to outputs. A single candidate function from this set is called a hypothesis (h). Learning = searching through H to find the hypothesis that best fits the training data.

Key Point

Choosing the model type (e.g., "only straight lines" vs "any polynomial") defines the hypothesis space. A bigger/richer hypothesis space can fit more complex patterns but also risks overfitting.

Real-world example

Imagine you are trying to guess a stranger's height using only their shoe size. If you decide the rule must be a straight line (height = a × shoe size + b), your hypothesis space is "all straight lines." If instead you allow any curve, your hypothesis space becomes much larger.

Worked Numerical Example

Suppose the hypothesis space is restricted to linear functions of the form h(x) = w·x + b, where w and b can each take one of 3 values: {0, 1, 2}.

Number of hypotheses in H = choices for w × choices for b = 3 × 3 = 9 hypotheses.

Each of the 9 combinations (w, b) is one candidate hypothesis; the learning algorithm's job is to pick the (w, b) pair that best fits the given training data (e.g., using least error).

Concept Check

True or False: "The hypothesis space contains only the one final model chosen after training."

Show Answer
False. The hypothesis space is the entire set of candidate models available before training; the "final model" is just one hypothesis selected from it.
Interactive Activity

If a hypothesis space allows decision rules of the form "IF attribute A = value v THEN Class = 1, ELSE Class = 0," and attribute A can take 4 possible values, how many distinct hypotheses exist in this space?

Show Answer
4 hypotheses — one for each possible value of v that A can take.

4. Inductive Bias

Definition

Inductive bias refers to the set of assumptions a learning algorithm uses to predict outputs for inputs it has never seen before. Since training data is always finite, some assumption is essential to "generalize" beyond it — without inductive bias, a learner cannot make any prediction on new data at all.

Remember

No inductive bias → No generalization. Every ML algorithm (Decision Tree, k-NN, Neural Network) has its own built-in bias (e.g., "prefer shorter trees," "nearby points have similar labels," "prefer smoother functions").

Real-world example

If you have only ever seen white swans, you might assume "all swans are white" — that assumption (bias) lets you predict the colour of a swan you've never seen. It could be wrong (black swans exist!), but without such an assumption you could never predict anything about a new swan at all.

Common Inductive Biases in Popular Algorithms
AlgorithmTypical Inductive Bias
k-Nearest Neighbour (k-NN)Points that are close in feature space tend to have the same label
Decision TreeShorter trees (simpler rules) are preferred over longer ones
Linear RegressionThe relationship between input and output is linear
Concept Check

True or False: "Inductive bias is a flaw in an algorithm that should always be removed."

Show Answer
False. Inductive bias is necessary — without some assumption about unseen data, a learning algorithm cannot generalize at all. The goal is to choose a bias that suits the problem, not eliminate it.
Interactive Activity — Fill in the Blank

5. Evaluation and Cross Validation

5.1 Why Evaluate a Model?

Definition

Evaluation is the process of measuring how well a trained model performs on data, using metrics such as Accuracy, Precision, Recall, or Mean Squared Error, so that we can trust its predictions on new, real-world data.

Key Point

Never evaluate a model only on the data it was trained on — that gives an overly optimistic (misleading) score. Always test on data the model has NOT seen during training.

5.2 Cross Validation

Definition

Cross Validation (CV) is a technique to evaluate a model reliably by repeatedly splitting the available data into training and testing subsets, so that every data point gets a chance to be tested on, giving a more trustworthy, less biased estimate of model performance.

Real-world example

A teacher testing a student's understanding using 5 different mock tests (each covering different topics) instead of just one, then averaging the scores — this gives a fairer estimate of the student's true ability than a single test.

5.2.1 K-Fold Cross Validation

Worked Numerical Example

Given a dataset of 100 samples and k = 5 (5-fold cross validation):

  • Data is split into 5 equal folds of 20 samples each.
  • Round 1: Fold 1 = Test (20 samples), Folds 2–5 = Train (80 samples) → compute accuracy A1
  • Round 2: Fold 2 = Test, remaining = Train → compute A2
  • ...continue until every fold has been the test set once (5 rounds total).
  • Final Accuracy = (A1 + A2 + A3 + A4 + A5) / 5

If the 5 round accuracies are 80%, 82%, 78%, 85%, 80%, then Final CV Accuracy = (80+82+78+85+80)/5 = 81%.

5.2.2 Leave-One-Out Cross Validation (LOOCV)

Definition

A special case of k-fold CV where k = n (n = total number of samples). In each round, exactly one sample is used as the test set and all remaining n−1 samples are used for training. This is repeated n times.

Q5. What is Inductive Bias? Why is it necessary in Machine Learning? 5 Marks

Answer:

Inductive Bias refers to the set of assumptions that a learning algorithm uses to predict outputs for inputs that were not part of the training data. Since any training dataset is finite while the space of possible inputs may be infinite, some assumption is essential to make predictions beyond the observed examples — this process is called generalization.

Why necessary: Without inductive bias, a learner has no basis to prefer one output over another for an unseen input, and cannot generalize at all.

AlgorithmTypical Inductive Bias
k-NNSimilar/nearby inputs have similar outputs
Decision TreeShorter (simpler) trees are preferred
Linear RegressionRelationship between input and output is linear

Example: Having only observed white swans, assuming "all swans are white" is an inductive bias that allows a prediction about a new, unseen swan — even though it might occasionally be wrong (e.g., black swans).

Q6. Explain Cross Validation and describe K-Fold Cross Validation with a numerical example. 5 Marks

Answer:

Cross Validation (CV) is a model evaluation technique that repeatedly partitions the available data into training and testing subsets, ensuring every data point is used for testing exactly once, resulting in a more reliable and less biased estimate of the model's true performance compared to a single train/test split.

K-Fold CV Procedure:

  • Divide the dataset randomly into k equal-sized folds.
  • In each of the k rounds, use one fold as the test set and the remaining (k−1) folds as the training set.
  • Compute the performance metric (e.g., accuracy) in each round.
  • Average the k performance values to get the final CV score.

Numerical Example: Dataset of 100 samples, k = 5. Each fold has 100/5 = 20 samples. If the 5 round accuracies obtained are 80%, 82%, 78%, 85%, 80%:

Final CV Accuracy = (80 + 82 + 78 + 85 + 80) / 5 = 405 / 5 = 81%

This average is a more trustworthy estimate of real-world performance than a single train-test split, since every sample contributed to testing exactly once.

🎯 Exam-Oriented Conclusion

Unit 1 builds the vocabulary that every future unit of this subject depends on: Machine Learning is fundamentally about learning patterns from experience (data) rather than following hand-coded rules, and the type of learning used — Supervised, Unsupervised, Semi-Supervised, or Reinforcement — depends entirely on what kind of data/feedback is available for the problem at hand. Every learning algorithm searches through a hypothesis space to find a good model, but this search is only possible, and generalization to unseen data only works, because of some inductive bias built into the algorithm. Finally, since a model is only useful if it performs well on data it hasn't seen, evaluation techniques like Cross Validation (especially K-Fold and LOOCV) are essential to get a trustworthy, unbiased estimate of real-world performance. For exams, focus on clear definitions, the comparison tables, and being able to classify a given scenario correctly — these are the most commonly asked question patterns.
