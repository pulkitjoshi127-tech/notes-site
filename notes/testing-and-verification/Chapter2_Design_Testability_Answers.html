Q1What do you mean by Design for Testability?5 Marks

Design for Testability (DFT) refers to a set of design techniques that add extra hardware/logic circuitry (and associated test methodology) to a chip during the design phase itself, with the specific goal of making the manufacturing test process easier, faster, and more effective at achieving high fault coverage.

  • DFT increases controllability (ease of setting internal nodes to desired values) and observability (ease of observing internal node values at outputs).
  • Adds structures like scan chains, test points, built-in self-test (BIST), and boundary scan.
  • Trades a small area/performance overhead for large reduction in test generation effort, test time, and test cost.
  • Essential because purely functional/ad-hoc testing of highly sequential VLSI circuits cannot achieve acceptable fault coverage within reasonable time.
Q2What is the goal of design for testability (DFT) and enlist three basic approaches of DFT?5 Marks

Goal

The goal of DFT is to improve the controllability and observability of internal circuit nodes so that manufacturing defects can be detected with high fault coverage using a minimum number of test vectors and minimum test application time/cost — while incurring acceptable area, power, and performance overhead.

Three Basic Approaches

ApproachDescription
Ad-hoc DFTApplication of general good-design practices and local circuit modifications (test points, partitioning) without a fixed, structured methodology
Structured DFT (Scan design)Systematic conversion of flip-flops into scan cells connected in shift-register chains, giving direct access to internal states
Built-In Self-Test (BIST)On-chip test pattern generation (e.g., LFSR) and response analysis (e.g., MISR) circuitry, allowing the chip to test itself with minimal external ATE dependency
Q3Enlist testability analysis techniques.5 Marks
  • SCOAP (Sandia Controllability/Observability Analysis Program): Computes numerical combinational and sequential controllability/observability measures for each circuit node.
  • Probability-based (Statistical) testability analysis: Uses signal probability propagation (Parker-McCluskey method) to estimate controllability/observability.
  • COP (Controllability/Observability Program): Similar probability-based technique estimating testability from 0 to 1.
  • Information-theoretic measures: Uses entropy concepts to quantify testability.
  • Simulation-based (fault simulation) testability analysis: Runs fault simulation to empirically estimate detectability of nodes.
  • Structural analysis (topological methods): Identifies redundant logic, reconvergent fanout, and feedback loops that hurt testability.

These techniques help identify hard-to-control/observe nodes early in the design cycle so that test points or DFT structures can be inserted at those locations.

Q4What is meant by verification plan? Discuss its importance in verification.5 Marks

A verification plan is a formal document prepared before verification begins, which defines the scope, strategy, features to be verified, testbench architecture, coverage goals, verification environment, and sign-off criteria for a design.

Contents of a Verification Plan

  • List of design features/functions to be verified
  • Verification approach/methodology (simulation, formal, emulation)
  • Testbench architecture and required verification IP
  • Coverage metrics (code coverage, functional coverage) and target goals
  • Resource, schedule, and sign-off/exit criteria

Importance

  • Provides a structured roadmap, avoiding ad-hoc/incomplete verification.
  • Ensures all critical design features are tracked and verified systematically.
  • Enables measurable, objective sign-off criteria (coverage closure).
  • Facilitates communication and review among design/verification teams.
  • Helps estimate schedule/resources and track verification progress.

Q7Describe Ad Hoc Approach for testability improvement.5 Marks

The Ad Hoc approach uses a collection of general design guidelines and localized circuit modifications to improve testability, without following any fixed/structured methodology (unlike scan design). It is typically applied where full structured DFT is too costly or unnecessary.

Common Ad Hoc Techniques

  • Partitioning large circuits into smaller, independently testable blocks using test points/multiplexers.
  • Adding test points: Control points (to improve controllability) and observation points (to improve observability) at critical nodes.
  • Bus-oriented test: Adding multiplexers to break long counter/register chains, allowing direct load/observe access.
  • Avoiding asynchronous logic/redundant logic and feedback loops that are inherently hard to test.
  • Initializing counters/registers with a reset signal for easy state initialization.
  • Breaking global feedback paths to convert into simpler, more testable structures.

Limitations

Ad-hoc methods are not systematic, are difficult to automate, require experienced designers, and do not guarantee a fault-coverage target — this is why structured approaches (scan, BIST) are preferred for large VLSI designs.

Q8Explain typical Scan Design Flow in detail.5 Marks
Fig: Typical scan design flow
  1. Scan (Design) Rule Check: Verify RTL/gate-level design conforms to scan-compatible design rules (no combinational feedback, controllable clocks, etc.).
  2. Scan Configuration: Decide scan architecture, number/length of chains, scan cell type.
  3. Scan Replacement: Replace functional flip-flops with scan flip-flops in the netlist.
  4. Scan Stitching: Connect scan cells serially to form complete scan chain(s), typically during/after placement for routing efficiency.
  5. Scan/ATPG Verification: Verify chain integrity (shift test) and generate/verify ATPG test patterns for high fault coverage.
Q9Explain following Scan Cell Designs: Muxed-D Scan Cell, Clocked-Scan Cell, LSSD Scan Cell5 Marks
Fig: Structures of Muxed-D, Clocked-scan, and LSSD scan cells
  • Muxed-D Scan Cell: A standard D-flip-flop with a 2:1 multiplexer added at its D input; Scan Enable (SE) selects between functional data (D) and scan data (SI). Simplest and most widely used since it needs no extra clock.
  • Clocked-Scan Cell: Uses separate scan clocks (instead of a mux) to load scan data through master-slave latches, avoiding the mux delay penalty on the functional path but needing extra non-overlapping clock signals.
  • LSSD Scan Cell: Built from two level-sensitive, non-overlapping-clocked latches (L1 master, L2 slave); insensitive to clock skew/timing hazards, providing very robust, race-free operation, at the cost of extra clock signal routing (typically requires 2–4 clocks: A, B, C).

Q11Explain Muxed-D full-scan design architecture in detail.5 Marks

In Muxed-D full-scan design, every flip-flop in the design is replaced by a Muxed-D scan flip-flop, and all scan flip-flops are connected together into one or more serial shift-register chains (scan-in → scan-out).

  • Each scan cell has a 2:1 mux at its D-input controlled by Scan Enable (SE): SE=1 selects scan-in data (SI) from previous cell; SE=0 selects normal functional data (D).
  • Operation modes:
    • Shift mode (SE=1): Test data is serially shifted into all flip-flops through the scan chain.
    • Capture/functional mode (SE=0): Combinational logic responses are captured into the flip-flops in one clock pulse.
  • Since all flip-flops are part of the scan chain, this is called full-scan — it gives complete controllability and observability of every state element, converting the sequential ATPG problem entirely into a combinational one.
  • Advantages: High fault coverage, simple/automatable test generation, easy scan insertion using standard EDA tools.
  • Disadvantages: Area overhead (extra mux per FF), small timing penalty on functional path, increased scan test time proportional to chain length.

The Mux-D scan cell places a 2:1 multiplexer before the D-input of a standard (level-sensitive) D flip-flop. SE=0 passes functional data D; SE=1 passes scan-in data SI, enabling serial shifting using the single system clock CK.

Q15Draw and explain LSSD scan cell design with necessary waveforms.5 Marks
Fig: Non-overlapping clock scheme for LSSD (A, B, C phases)

L1 (master latch) is clocked by system clock (C1) in functional mode, or shift clock A during scan-shift; L2 (slave latch) is clocked by shift clock B (or C2/C3), holding the output stable. Because both latches are level-sensitive (not edge-triggered) and clocked by strictly non-overlapping pulses, the design is inherently free from clock-skew-induced races — data can never "race through" both latches in the same clock phase, making LSSD extremely robust for scan shifting regardless of interconnect delay variations.

Q17Draw and explain Enhanced Scan Architecture.5 Marks
Fig: Enhanced scan cell — additional hold latch stores current state during two-pattern delay/at-speed test

Enhanced scan architecture adds an extra hold-latch to each standard scan cell, which can store the current (first) test-pattern value while the scan chain shifts in the next pattern in the background. This allows generation of the two-vector sequences needed for delay/transition fault testing without needing an extra full shift cycle between the two vectors, enabling faster, more efficient at-speed delay testing than standard scan (which must shift completely between the two vectors of a delay test).

Q20What do you mean by Scan Design Rules?5 Marks

Scan design rules are a set of RTL/gate-level coding and structural restrictions that a design must satisfy before scan insertion, ensuring that scan chains shift correctly and that ATPG can generate high-coverage tests.

  • All flip-flops must be clocked by controllable clock signals (no internally-generated/gated clocks reaching flip-flops directly without control).
  • No combinational feedback loops (they prevent proper level-sensitizing and can cause oscillation during shift/capture).
  • Set/Reset (asynchronous) signals must be controllable from primary inputs and must be inactive during scan shift, to avoid corrupting scan data.
  • Tri-state buses must not be allowed to float or contend during scan test (bus contention rules).
  • Derived/gated clocks must be handled specially (see Q22) to avoid clock-skew or double-clocking issues during shift.
  • Every scan flip-flop must be reachable and controllable through the defined scan-in/scan-out ports.
Q21Explain Control point insertion.5 Marks
Fig: Multiplexer-based control point forcing a node to a known test value

Control point insertion is an ad-hoc DFT technique where a multiplexer (or gating logic) is inserted on a hard-to-control internal signal line, allowing an external Test Control (TC) signal to directly force the line to a known 0 or 1 value during test mode, bypassing its normal driving logic.

  • Improves controllability of nodes that are otherwise deeply embedded and difficult to set from primary inputs.
  • Commonly used at reset lines, enable lines, or nodes feeding hard-to-reach fan-in cones.
  • Adds small area/delay overhead (mux in the signal path) but significantly reduces test generation difficulty and improves fault coverage for that region of logic.
Q22What is the scan-design rule for derived-clock style? Give recommended solution with an example.5 Marks

A derived clock is a clock signal generated internally by combinational logic (e.g., gated clock = CK AND Enable, or a clock divider) rather than coming directly from a primary clock pin. Scan design rule: flip-flops should not be clocked directly by an internally-derived/gated clock during scan shift, because uncontrolled glitches on the derived clock during shift can cause unintended, uncontrolled clocking of the flip-flop (double-clocking or missed-clocking), corrupting the scan chain.

Recommended Solution

  • Bypass the clock-gating logic during scan (test) mode using a test-mode multiplexer/OR-gate, so the flip-flop is driven directly by the primary/global clock when Scan Enable is active.
  • Example: For a gated clock GCK = CK AND EN, insert: GCK_test = CK AND (EN OR Test_Mode) — ensuring the gate is always transparent during scan shift regardless of the functional Enable value.

Q25Explain scan stitching.5 Marks

Scan stitching is the process of connecting the scan-out (SO) pin of one scan cell to the scan-in (SI) pin of the next scan cell, in the order determined during scan configuration, to form one continuous serial shift-register chain (or multiple parallel chains) from the chip's scan-in port to its scan-out port.

  • Typically performed after (or during) physical placement, so cells physically close together are stitched together — minimizing scan-chain routing length/congestion.
  • The order of stitching may differ from the logical/RTL declaration order (see Scan Reordering) to optimize layout.
  • Correct stitching must be verified (scan chain integrity/shift test) to ensure no cell is skipped, duplicated, or mis-ordered.
  • Automated by Place-and-Route/DFT tools using the scan configuration file generated earlier in the flow.
Q27Discuss scan configuration and its importance in scan design flow. (Also: Explain the Role of Scan Configuration in the scan design flow.)5 Marks

Scan configuration is the planning stage of the scan design flow where the overall scan architecture and its parameters are decided before any physical scan insertion takes place (see Chapter 1, Q15 for the detailed list of decisions: architecture type, cell type, number/length/balancing of chains, clock/reset handling, and pin allocation).

Importance

  • Determines the trade-off between test time (chain length), pin/routing overhead (number of chains), and achievable fault coverage.
  • Poor configuration (e.g., unbalanced chain lengths) increases test application time unnecessarily.
  • Correct handling of clock/reset domains at this stage avoids costly re-design later in the flow.
  • Provides the configuration data needed by later stages (replacement, stitching) to automate scan insertion correctly.
  • Directly impacts ATPG efficiency and the final test pattern count/fault coverage achieved.
Q29What is a combinational feedback loop? How is it avoided in scan design?5 Marks

A combinational feedback loop is a closed cycle of purely combinational gates (no flip-flop in the loop) where the output of a gate eventually feeds back, through other combinational gates, to one of its own inputs.

Fig: Combinational feedback loop between gates G1–G2

Problems Caused

  • Makes the circuit behave like an unintended latch/oscillator, with unpredictable/unstable logic values.
  • Prevents deterministic sensitization needed for D-algorithm/ATPG-based test generation.
  • Standard SCOAP/topological analysis assumes an acyclic combinational structure — a loop breaks this assumption.

Avoidance in Scan Design

  • Identify feedback loops during scan rule checking (structural/topological analysis).
  • Break the loop by inserting a scan flip-flop, or a test-mode multiplexer that opens the loop during test mode, converting it into an acyclic (properly testable) structure.
  • Redesign the RTL to avoid latches/combinational loops from the outset, following synchronous design guidelines.
Q30Find out SCOAP and Probability based testability measures for 5-input NAND gate.5 Marks

Assume all 5 inputs (i1...i5) are primary inputs: CC1 = CC0 = 1 for each.

SCOAP Combinational Controllability

NAND rule: CC0(y) = CC1(i1)+CC1(i2)+CC1(i3)+CC1(i4)+CC1(i5) + 1 = 5(1) + 1 = 6
CC1(y) = min[CC0(i1),...,CC0(i5)] + 1 = 1 + 1 = 2

Observability (assuming y is a primary output, CO(y) = 0): CO(ik) = CO(y) + Σj≠k CC1(ij) + 1 = 0 + 4(1) + 1 = 5 for each input.

Probability-Based (Signal Probability) Measure

Assuming each input has signal probability P1 = 0.5:

P1(y) = 1 − (P1(i1)·P1(i2)·P1(i3)·P1(i4)·P1(i5)) = 1 − (0.5)5 = 1 − 1/32 = 31/32 = 0.969
P0(y) = 1 − P1(y) = 1/32 = 0.031

Observability probability for each input (needs all other 4 inputs = 1 to sensitize): PO(ik) = PO(y) × (0.5)4 = 1 × 1/16 = 0.0625 (assuming y directly observable, PO(y)=1).

Q33Draw and Explain RTL testability repair design flow.5 Marks
Fig: RTL testability repair flow
  1. RTL Design input: Start with the synthesizable RTL description of the circuit.
  2. Testability Analysis: Run SCOAP or probability-based analysis on the RTL/gate-level netlist to compute controllability/observability of every node.
  3. Identify hard-to-test nodes: Flag nodes with poor (high) CC/CO values exceeding a threshold.
  4. Insert repair (test points): Add control points and/or observation points at the identified nodes to improve their testability.
  5. Re-analyze/verify: Re-run testability analysis to confirm improvement, iterating until acceptable testability is achieved without excessive area/performance overhead.
Q34Why do we need DFT techniques? Define Controllability and Observability.5 Marks

Need for DFT

  • Modern VLSI chips have billions of gates/transistors — exhaustive functional testing is computationally infeasible.
  • Sequential circuits have poor natural controllability/observability of internal states (see Chapter 1, Q14).
  • DFT reduces test generation time, test application time, and improves achievable fault coverage at reasonable cost.
  • Enables automated, high-quality test pattern generation using standard ATPG tools.

Definitions

Controllability: The degree of difficulty/ease of setting a specific node in the circuit to a required logic value (0 or 1) by applying signals at the primary inputs.

Observability: The degree of difficulty/ease of observing the logic value at a specific internal node by propagating it to a primary output.

Q36What is meant by Testability? Explain Testability Analysis. (Also: Define Controllability, Observability, Testability and list testability analysis techniques.)5 Marks

Testability is a measure of how easy or difficult it is to test a circuit for the presence of manufacturing faults — a circuit with high controllability and high observability at all its internal nodes is said to have high testability, meaning fewer/simpler test patterns are needed to achieve high fault coverage.

Testability Analysis is the process of computing numerical (or probabilistic) controllability and observability values for every node in a circuit, without actually generating test patterns, in order to quickly and cheaply predict which parts of the circuit will be difficult to test — guiding designers to apply DFT (test points, scan) at those specific locations early in the design cycle, well before ATPG is run.

See Q3 above for the list of testability analysis techniques (SCOAP, probability-based/COP, information-theoretic, simulation-based, structural analysis).

CC0(Sum) = min[CC0(X1)+CC1(Cin), CC1(X1)+CC0(Cin)]+1 = min[4,4]+1 = 5
CC1(P1) = CC1(A)+CC1(B)+1 = 3; CC0(P1) = min[CC0(A),CC0(B)]+1 = 2
CC1(P2) = CC1(X1)+CC1(Cin)+1 = 5; CC0(P2) = min[CC0(X1),CC0(Cin)]+1 = 2
CC1(Cout) = min[CC1(P1),CC1(P2)]+1 = min[3,5]+1 = 4
CC0(Cout) = CC0(P1)+CC0(P2)+1 = 2+2+1 = 5

Observability of A, B, Cin is obtained by propagating through both the Sum path (via XOR gates) and the Cout path (via AND/OR gates) and taking the minimum of the two path values, using the observability rule stated in Q31 (this multi-path tracing is characteristic of full-adder testability calculation, reflecting its reconvergent structure).

Q41Write probability-based controllability & observability calculation rules for logic gates.5 Marks

The probability-based (Parker-McCluskey) model represents controllability as the signal probability P1 (probability the line is at logic 1) and P0 = 1−P1.

GateP1(y)
ANDP1(a) × P1(b)
OR1 − [(1−P1(a))(1−P1(b))]
NAND1 − [P1(a) × P1(b)]
NOR(1−P1(a))(1−P1(b))
NOT1 − P1(a)
XORP1(a)+P1(b) − 2·P1(a)·P1(b)

Observability Probability (PO)

PO(input) = PO(output) × P(other inputs set to their non-controlling value):

  • AND/NAND: PO(a) = PO(y) × P1(b) (other input must be 1)
  • OR/NOR: PO(a) = PO(y) × P0(b) (other input must be 0)
Q42Calculate probability-based measures for a 3-input OR gate.5 Marks

Assume each input has P1 = 0.5 (equally likely 0/1).

P1(y) = 1 − (1−0.5)(1−0.5)(1−0.5) = 1 − (0.5)3 = 1 − 0.125 = 0.875
P0(y) = 1 − 0.875 = 0.125

Observability of each input (needs other two inputs = 0 to sensitize, non-controlling value for OR is 0): assuming y is directly observed (PO(y)=1):

PO(input) = PO(y) × P0(other1) × P0(other2) = 1 × 0.5 × 0.5 = 0.25
Q43Obtain Controllability & Observability for signals of a 2-input AND gate using SCOAP and probability methods.5 Marks

SCOAP Method

Primary inputs: CC1(a)=CC0(a)=CC1(b)=CC0(b)=1

CC1(y) = CC1(a)+CC1(b)+1 = 1+1+1 = 3
CC0(y) = min[CC0(a),CC0(b)]+1 = 1+1 = 2
CO(a) = CO(y)+CC1(b)+1 = 0+1+1 = 2   (assuming y is primary output)
CO(b) = CO(y)+CC1(a)+1 = 0+1+1 = 2

Probability Method

Assume P1(a)=P1(b)=0.5

P1(y) = P1(a) × P1(b) = 0.5 × 0.5 = 0.25;   P0(y) = 0.75
PO(a) = PO(y) × P1(b) = 1 × 0.5 = 0.5
PO(b) = PO(y) × P1(a) = 1 × 0.5 = 0.5

Both methods show line "y" is easier to control to 0 than 1 (fewer AND inputs need to align for 1), and both inputs are symmetric in observability due to the gate's symmetric structure.

Q45Derive combinational & sequential controllability/observability equations for sites a, b, d, r, CK, q in the given D-FF circuit.5 Marks
Fig: d = a·AND·b; D-FF with reset r, clock CK, output q

Assume a, b, r, CK are primary inputs: CC1(a)=CC0(a)=CC1(b)=CC0(b)=CC1(r)=CC0(r)=CC1(CK)=CC0(CK)=1.

Combinational Controllability (site d)

CC1(d) = CC1(a)+CC1(b)+1 = 1+1+1 = 3
CC0(d) = min[CC0(a),CC0(b)]+1 = 1+1 = 2

Sequential Controllability (site q)

To set q=1, D must be set to 1 (via a=b=1) and one clock pulse applied; to set q=0, either D=0 with a clock pulse, or the (faster) reset path r can be asserted directly:

SC1(q) = CC1(d) + CC1(CK) + 1 = 3+1+1 = 5
SC0(q) = min[ CC0(d)+CC1(CK)+1 , CC1(r)+1 ] = min[2+1+1, 1+1] = min[4,2] = 2 (via reset — the faster path)

Observability (assume q is primary output, CO(q)=0)

CO(d) = CO(q) + CC1(CK) + 1 = 0+1+1 = 2
CO(a) = CO(d) + CC1(b) + 1 = 2+1+1 = 4
CO(b) = CO(d) + CC1(a) + 1 = 2+1+1 = 4
CO(r) = CO(q) + 1 = 0+1 = 1  (reset directly forces/is observed at q)
CO(CK) is implicit — its correct value/edge is a precondition for capturing d into q, rather than a propagated data value

This shows the reset path r gives the fastest (lowest-cost) way to control q to 0, and that a, b are the "deepest" (least controllable/observable) nodes since they must pass through both the AND gate and the flip-flop's clocked capture to reach the observable output q.
